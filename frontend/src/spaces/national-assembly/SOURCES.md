# National Assembly space: asset sources

Where every file in `assets/` comes from and under which terms it may be used.

The files in `assets/` are the optimised runtime set written by `scripts/spaces/optimize-assets.mjs`
(geometry compressed with meshopt, textures stored once each as `textures/<content-hash>.ktx2`).
The uncompressed source models and the Blender scene are not in this repository; the per-file
before/after record of the last run is in `scripts/spaces/reports/`.

Generated by the build script, with no third-party content: all stonework (fountain basin,

Reference photographs of the real building (Wikimedia Commons) were looked at for proportions
only. None is shipped or used as a texture.

## Regenerating the locomotion clips

From the repository root, with the two source GLBs downloaded from three.js r187
(`examples/models/gltf/Xbot.glb` and `examples/models/gltf/Soldier.glb`) into `anim-src/`:

```
node scripts/avatar/build-avatar-animations.mjs --source anim-src/Xbot.glb --clip-source Run=anim-src/Soldier.glb
```

The tool is deterministic, prints a validation report (limb-direction error against the source,
foot heights, loop continuity, symmetry, measured ground speed) and exits with an error if a check
fails. Leave out `--clip-source` to take all three clips from Xbot.

## Regenerating the runtime assets

With the source models in a folder (the nine GLBs as delivered by the modeller):

```
npm ci --prefix scripts/spaces
node scripts/spaces/optimize-assets.mjs --source <folder>
```

The run is deterministic, checks the result with three's own loader (node names, collision
probes, door pivots, vegetation levels, texture transcoding) and fails if any file would exceed
45 MB.
