# 프로젝트 문서 뷰어 — 연/월/일 분류 내비게이션 설계

작성일: 2026-07-29
상태: 설계 승인됨

## 목적

어드민의 **프로젝트 문서** 메뉴(`/admin/docs/*`)에서 로그성 문서를 연·월·일로 탐색할 수
있게 한다. 특히 작업일지가 대상이다.

현재 [`AdminDocs.jsx`](../../../frontend/src/pages/admin/AdminDocs.jsx)는 문서 content
전체를 `ReactMarkdown` 한 번에 넘긴다. 작업일지는 **1,727줄 / 136KB**라 열면 4개월치
기록이 한 페이지에 통째로 쏟아진다. 원하는 날짜를 찾으려면 브라우저 스크롤과
Ctrl+F에 의존해야 한다.

## 현황

| 문서 | 형태 | 규모 | 날짜 구조 |
|---|---|---|---|
| `work-log.md` | `## YYYY-MM-DD` 섹션 | 1,727줄 / 136KB | 날짜 섹션 29개 (2026-04 ~ 2026-07) |
| `bugfix-log.md` | 마크다운 표 | 39KB / 75행 | `날짜` 컬럼 |
| `upgrade-log.md` | 마크다운 표 | 18KB / 84행 | `날짜` 컬럼 |
| `dev-plan.md` 외 | 일반 문서 | — | 날짜 없음 (대상 아님) |

저장 경로: `docs/*.md` → 서버 기동 시 [`main.py`](../../../backend/main.py) `_seed_docs()`가
`Document` 테이블(key/title/content)에 통째로 upsert → 프론트가 content 전체를 렌더.

### 부수적으로 교정되는 문제

`work-log.md`에서 2026-04-08 섹션(231행)이 2026-04-07 섹션(285행)보다 앞에 있다.
설계상 항상 날짜 내림차순으로 정렬하므로 화면에서는 자동 교정된다. 원본 파일은
건드리지 않는다.

## 결정된 방침

| 항목 | 결정 | 이유 |
|---|---|---|
| 분류의 실체 | **뷰어(UI)에서만** | `.md` 파일·DB·`/end` 스킬·git 이력 모두 무수정. 회귀 위험 최소 |
| 적용 범위 | **로그 3종 전부** | 작업일지·버그수정·업그레이드가 같은 인터랙션으로 동작 |
| 기본 화면 | **타임라인 목록** | 전체 흐름 파악이 가장 빠름 |
| 검색박스 | **넣지 않음** | YAGNI. 필요해지면 별도로 |

## 1. 데이터 모델 — 문서를 "엔트리 배열"로 정규화

세 문서는 겉모습(섹션 vs 표)만 다를 뿐 속은 **날짜가 붙은 기록**으로 동일하다.
파서 두 개가 같은 타입을 뱉게 하면 화면 코드는 하나로 끝난다.

`frontend/src/utils/docEntries.js` — 순수 함수. DOM·API 의존 없음.

```js
// 엔트리
{ date: "2026-04-29", year: 2026, month: 4, title: "OpenClaw 보안 감사 + Phase 0 #1 적용", body: "…markdown…" }

// 날(day) 그룹 — 같은 날짜 엔트리를 묶은 단위
{ date: "2026-05-01", year: 2026, month: 5, entries: [ …3개… ] }
```

### 함수

| 함수 | 입력 | 동작 |
|---|---|---|
| `parseSectionDoc(md)` | 작업일지 | `## YYYY-MM-DD (제목)` 기준 분할. 괄호 안이 제목, 괄호가 없으면 제목 없이 날짜만 |
| `parseTableDoc(md)` | 버그수정·업그레이드 | 첫 마크다운 표를 행 단위로. 헤더에서 `날짜` 컬럼 위치를 자동 탐지, **그 다음 컬럼이 제목**(버그수정=`버그 설명`, 업그레이드=`변경 내용`), 나머지 컬럼은 본문 |
| `parseDoc(md)` | 모든 문서 | 위 둘을 순서대로 시도. 엔트리 0개면 `null` 반환 |
| `groupByDate(entries)` | 엔트리 배열 | 날짜별 병합 → 날 그룹 배열. 날짜 **내림차순** |

`parseDoc`이 `null`을 반환하면 호출부는 **기존 통짜 렌더로 fallback**한다. 개발계획·
Orbitron 서버·픽셀스트리밍 서버 등 날짜 없는 문서는 지금과 100% 동일하게 동작한다.

### 같은 날짜 병합

`2026-05-01`은 세션 3개, `2026-04-15`·`2026-04-18`·`2026-04-24`는 각 2개다. 이들을 카드
여러 장으로 흩지 않고 **날 그룹 하나 + `세션 3` 배지**로 묶는다. 목록이 조밀해지고,
상세 URL이 날짜만으로 유일해진다.

작업일지 기준 실측: 섹션 **29개** → 날 그룹 **24개** (4월 16 · 5월 5 · 6월 2 · 7월 1).

## 2. 화면 구조

2단 레이아웃. 좌측 sticky 연/월 인덱스 + 우측 본문.

**전역 관리자 사이드바([`Sidebar.jsx`](../../../frontend/src/components/layout/Sidebar.jsx))는
건드리지 않는다.** 이미 스크롤이 필요할 만큼 깊고, 거기에 연/월/일을 넣으면 다른 메뉴를
볼 때까지 따라다닌다.

```
PROJECT DOCUMENTATION
작업일지                                  24일 · 29세션 · 2026.04 – 07
┌──────────┬──────────────────────────────────────────────────┐
│ 2026     │  2026년 7월                                       │
│  07월  1 │  ┌────────────────────────────────────────────┐  │
│  06월  2 │  │ 07-29  Lucifer 공동 작업공간 구축          │  │
│  05월  5 │  │        claude-max 인증 복구 → 미디어…       │  │
│  04월 16 │  └────────────────────────────────────────────┘  │
│          │  2026년 6월                                       │
│          │  ┌────────────────────────────────────────────┐  │
│          │  │ 06-23  OpenClaw Codex 토큰 복구            │  │
│          │  └────────────────────────────────────────────┘  │
└──────────┴──────────────────────────────────────────────────┘
```

### 인터랙션

| 대상 | 동작 |
|---|---|
| 좌측 **연** 클릭 | 그 해만 목록에 남김. 다시 누르면 해제 |
| 좌측 **월** 클릭 | 그 달만 목록에 남김. 다시 누르면 해제 |

필터는 **한 번에 하나만 활성**이다. 연을 고른 상태에서 월을 고르면 월 필터로 바뀐다
(연+월 조합 상태를 따로 두지 않는다). 아무것도 안 고르면 전체.
| **작업일지 카드** 클릭 | 그 날 본문 전체 렌더(세션 여러 개면 이어서) + breadcrumb + 이전/다음 날 이동 |
| **표형 카드** 클릭 | 페이지 이동 없이 인라인 확장 — 원인·수정내용·관련파일 |

표형을 별도 페이지로 보내지 않는 이유: 엔트리 본문이 표 한 행이라 페이지를 갈아끼울
분량이 아니다.

### 상세 화면 (작업일지)

```
작업일지 › 2026 › 04월 › 04-29                    ← 이전 날    다음 날 →

2026-04-29 (OpenClaw 보안 감사 + Phase 0 #1 적용 · Windows Node 도입 설계)
  작업 요약   … 표 …
  세부 내용   … 목록 …
```

## 3. 라우팅

| 경로 | 화면 |
|---|---|
| `/admin/docs/:docKey` | 타임라인 |
| `/admin/docs/:docKey/:date` | 그 날 상세 (**신규**) |

[`App.jsx`](../../../frontend/src/App.jsx) 73행의 기존 라우트를 `:date?` 옵셔널 파라미터로
교체한다(react-router 7.14 지원). 라우트를 둘로 나누면 목록↔상세 이동 때 컴포넌트가
언마운트돼 136KB를 매번 다시 받는다. 딥링크와 새로고침은 그대로 유지된다.
표형은 URL을 바꾸지 않고 로컬 state로 펼친다.

존재하지 않는 날짜로 진입하면 타임라인으로 되돌리고 "해당 날짜의 기록이 없습니다"
안내를 띄운다.

## 4. 엣지케이스

| 상황 | 처리 |
|---|---|
| 날짜 순서 역전 (04-08 → 04-07) | 항상 내림차순 정렬 → 화면에서 교정. 원본 무수정 |
| 표에서 날짜 파싱 실패한 행 | 버리지 않고 **"기타" 그룹**으로 모아 표시 |
| 엔트리 0건 / 파싱 실패 | 기존 통짜 렌더로 fallback — 회귀 위험 0 |
| 로딩 중 | 스켈레톤 (현재는 "로딩 중..." 텍스트) |
| API 실패 | 기존 동작 유지 — "문서를 불러올 수 없습니다." |

### 전송량

뷰어 단계 분류이므로 브라우저는 여전히 136KB를 받는다. 줄어드는 것은 **렌더 부담**이다.
파싱은 `useMemo`로 content가 바뀔 때만 수행한다.

나중에 전송량이 문제가 되면 백엔드에 목차/엔트리 API를 추가하는 쪽으로 올라가면 되고,
그때도 `docEntries.js`의 파서 코드를 그대로 서버로 옮기면 된다. 지금 이 설계가 그 길을
막지 않는다.

## 5. 테스트

파서가 순수 함수라 테스트가 잘 붙는다. 다만 **프론트엔드에 테스트 러너가 없다**
(`package.json`에 vitest 없음). `vitest`를 devDependency로 추가하고 `npm test` 스크립트를
넣는다. Vite 프로젝트 표준 조합이라 설정 부담이 거의 없다.

`frontend/src/utils/docEntries.test.js` — 실제 문서 발췌를 fixture로 사용:

| 검증 | 기대 |
|---|---|
| 작업일지 섹션 파싱 | 엔트리 29개 |
| 같은 날짜 병합 | `2026-05-01` 날 그룹 1개, 그 안에 엔트리 3개 |
| 정렬 역전 교정 | 그룹 배열에서 `04-08`이 `04-07`보다 뒤 |

| 날짜 없는 문서 | `parseDoc()` → `null` |

## 구현 중 바뀐 결정 3건

구현과 리뷰 과정에서 이 설계의 판단 세 가지가 뒤집혔다. 이 문서를 나중에 읽는 사람은
아래가 최종 동작이다.

### 1. 타임라인 대상은 자동 판별이 아니라 명시 목록

위 1장은 `parseDoc`이 문서 형태를 자동 판별한다고 썼다. 실제로는 **`work-log` ·
`bugfix-log` · `upgrade-log` 세 키만** 타임라인을 받는다
(`frontend/src/components/docs/timelineDocs.js`).

자동 판별은 사고 반경이 너무 넓었다. `docs/dev-plan.md`의 첫 표가
`| 단계 | 목표 | 상태 | 예정일 |`인데, `예정일`을 `날짜`로 한 번만 고치면 개발계획서
본문 전체가 7장짜리 카드 목록으로 바뀌어 사라진다. `/end` 스킬이 이 표를 직접 편집하므로
가설이 아니라 시간 문제였다. 새 로그 문서를 추가할 땐 그 파일의 배열에 키를 한 줄 넣는다.

### 2. 제목 없는 섹션은 본문에서 요약을 끌어온다

`/end`는 `## YYYY-MM-DD`만 쓰고 괄호 제목을 달지 않는다. 29개 섹션 중 11개가 그렇고
앞으로 쌓이는 건 전부 그렇다. 위 1장의 "괄호가 없으면 제목 없이 날짜만" 규칙을 그대로
두면 카드가 `04-04` … `2026-04-04`로 날짜를 두 번 찍는다.

최종 규칙은 **괄호 제목 → 본문 유래 요약 → 없음**이다. 요약은 섹션의 `### 작업 요약`
표에서 첫 작업 항목을, 표가 없으면 첫 불릿을 끌어온다 (`deriveSummary`,
`frontend/src/utils/docEntries.js`). 실제 11개 전부에서 유효한 요약이 나오는 것을 확인했다.

### 3. 표형 문서는 `:date` 세그먼트를 무시한다

3장의 라우트 표는 모든 문서에 상세 경로가 있는 것처럼 읽힌다. 표형 문서는 엔트리 본문이
`""`이므로 `/admin/docs/bugfix-log/2026-04-04`가 빈 상세 페이지를 띄웠다. 최종 동작은
**상세 화면은 섹션형 문서 전용**이고, 표형 문서에 날짜가 붙어 들어오면 타임라인을 보여준다
(URL은 그대로 두어 뒤로가기와 싸우지 않는다).
